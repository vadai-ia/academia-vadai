## Lo que se construyó

| Dónde | Qué |
|---|---|
| `/admin/lecciones/[id]` | Builder: preguntas con opciones, marcar la correcta, reordenar, puntaje mínimo y si revela respuestas |
| `/curso/[slug]/[leccionId]` | El quiz del alumno, con calificación inmediata y reintentos ilimitados |

### La respuesta correcta no existe para el navegador

Es lo que M1 dejó preparado y aquí se ejerce:

- La tabla `quiz_questions` es **admin-only** por RLS
- El alumno lee `academia.quiz_questions_public`, la vista que **no proyecta**
  `correct_option_id`
- La prueba verifica que la cadena `correct_option_id` **no aparezca** en el HTML
  que recibe el alumno

### Calificar exige service role, y eso es peligroso

Leer la respuesta correcta requiere saltarse RLS. Sin cuidado, cualquier alumno
podría calificar el quiz de un curso que no compró.

La defensa está en el orden de las operaciones:

1. Primero se consulta el quiz **con el cliente del usuario**, donde RLS sí
   aplica. Si esa consulta no devuelve nada, se corta ahí.
2. Solo después entra el service role, y **únicamente** para leer las respuestas
   correctas.

La prueba confirma el efecto: el alumno vencido ni siquiera abre la lección, y
termina con cero intentos.

### Reprobar no revela las respuestas

Con `reveal_answers = false` —el default— fallar no muestra cuál era la correcta.
Si las revelara, los reintentos ilimitados se volverían "falla una vez y copia".
Es configurable por quiz, y el builder lo dice en pantalla.

Al **aprobar** sí se revelan: ya no hay nada que proteger y sirve para repasar.

### Las respuestas se leen contra la lista real

El servidor no itera lo que mandó el cliente sino las preguntas que existen en la
base. Campos de más no cuentan; campos de menos se toman como error, no como
pregunta inexistente. Así, manipular el formulario no cambia el denominador.

### El quiz es un formulario

Se escribió primero con `onClick` y `useTransition`, lo que lo dejaba dependiendo
de JavaScript y sin forma de probarlo por HTTP. Se convirtió a `<form>` con
server action, como el resto de la app: funciona sin JS y la prueba lo ejerce por
la ruta real.

## La matriz

| Grupo | Qué demuestra |
|---|---|
| **La correcta no sale** | El quiz renderiza sus 5 preguntas y el HTML no contiene `correct_option_id`; se muestra el puntaje mínimo |
| **Reprobar** | Todas mal → 0%, reprobado, la lección **no** queda completa y **no** se revelan las correctas |
| **Aprobar** | Todas bien → 100%, aprobado, **la lección queda completa** y el curso avanza a 25% |
| **Sin acceso** | El alumno vencido no abre la lección y termina con cero intentos |

Los dos intentos quedan guardados: reintentos ilimitados significa historial, no
sobrescritura.

---

## Fuera de alcance de M5

Preguntas abiertas o de opción múltiple con varias correctas (§3.4 dice "una
correcta"). Banco de preguntas reutilizable entre cursos. Límite de tiempo.
Nada de eso está en el spec.

El certificado (M10) leerá estos intentos para decidir si el alumno aprobó los
quizzes obligatorios.
